# AWX offline installer for Ubuntu 24.04 (k3s + AWX Operator)

Automated, **offline / air-gap-capable** installation of the open-source
[Ansible AWX](https://github.com/ansible/awx) on a fresh **Ubuntu 24.04 LTS**
server. AWX runs on a single-node **k3s** cluster and is managed by the
**AWX Operator**. Everything is driven by bash.

Unlike Harbor, AWX ships **no single offline-installer tarball**, so we vendor
the pieces ourselves into `./vendor`:

| Component | Pinned version | Source |
|---|---|---|
| k3s (binary + airgap images + install script) | **v1.30.6+k3s1** | k3s-io/k3s releases |
| AWX Operator (kustomize source + image) | **2.19.1** | ansible/awx-operator |
| AWX | **24.6.1** | quay.io/ansible/awx |
| AWX Execution Environment | **24.6.1** | quay.io/ansible/awx-ee |
| PostgreSQL | **postgresql-15-c9s:20260624** | quay.io/sclorg |
| Redis | **7.4.9** | docker.io/redis |
| Projects init container | **centos:stream9** (pinned by digest) | quay.io/centos |

All container images are exported to `vendor/images/*.tar` and imported directly
into k3s's containerd store, so **nothing is pulled from a registry at install
time**. Versions are pinned in [`vendor/manifest.env`](vendor/manifest.env), the
single source of truth for both fetching and installing.

## Layout

```
.
├── fetch-assets.sh              # downloads k3s + operator + saves images (run with internet)
├── install.sh                   # top-level installer (run on the target, as root)
├── uninstall.sh                 # tear down (optionally --purge k3s itself)
├── config.env.example           # copy to config.env and edit
├── config/
│   ├── awx.yaml.tmpl            # AWX custom resource template
│   └── kustomization.yaml.tmpl  # operator kustomization template
├── certs/
│   └── README.md                # only needed for ingress TLS (BYO cert)
├── scripts/
│   ├── lib.sh                   # shared helpers (logging, manifest/config loading)
│   ├── 00-preflight.sh          # OS/arch/asset/cert/checksum/port checks
│   ├── 10-install-k3s.sh        # offline k3s install (SKIP_DOWNLOAD)
│   ├── 20-load-images.sh        # ctr images import into k3s containerd
│   ├── 30-deploy-operator.sh    # kustomize-apply awx-operator from vendored src
│   └── 40-deploy-awx.sh         # render + apply the AWX custom resource
└── vendor/
    ├── manifest.env             # pinned versions + URLs
    ├── SHA256SUMS               # integrity manifest (generated by fetch-assets.sh)
    ├── k3s/                     # k3s binary, install.sh, airgap images (populated by fetch)
    ├── operator/                # awx-operator-*.tar.gz (populated by fetch)
    └── images/                  # *.tar image exports (populated by fetch)
```

## Usage

### 1. Fetch dependencies (on any machine with internet)

```bash
./fetch-assets.sh
```

Downloads the pinned k3s release and awx-operator source, and exports the AWX
container images to `vendor/images/`, then writes `vendor/SHA256SUMS`. Image
export uses **`docker`** on the fetch host; if docker isn't installed,
`fetch-assets.sh` installs it automatically (via `apt` on Ubuntu/Debian) and
starts its daemon. This step runs on the online fetch host only — it changes
nothing on the air-gapped target. Afterward the whole repo can be copied to the
target (`rsync`, USB, `git add -f vendor/...`).

### 2. Configure (on the target)

```bash
cp config.env.example config.env
$EDITOR config.env            # set AWX_HOSTNAME, admin password, nodeport, storage
```

For ingress TLS only, place your cert/key in `certs/` — see
[`certs/README.md`](certs/README.md). The default NodePort access needs no cert.

### 3. Install (on the target, as root)

```bash
sudo ./install.sh
```

This runs, in order: preflight checks → install k3s offline → import AWX images
into containerd → deploy the AWX Operator with kustomize → render and apply the
AWX custom resource. The operator then reconciles AWX into running pods.

```bash
sudo k3s kubectl -n awx get pods -w        # watch it come up
```

When ready, AWX is at `http://<host>:30080/` (NodePort default), login `admin` /
your `AWX_ADMIN_PASSWORD`. **Change the admin password after first login.**

### Manage / tear down

```bash
sudo k3s kubectl -n awx get awx,pods            # status
sudo ./uninstall.sh                             # remove AWX + operator namespace
sudo ./uninstall.sh --purge                     # also uninstall k3s (nukes cluster)
```

## Notes & troubleshooting

- **Idempotent:** re-running `install.sh` skips k3s install / operator extraction
  if already done and re-applies manifests. Safe to retry.
- **Integrity:** preflight runs `sha256sum -c vendor/SHA256SUMS` and refuses to
  proceed if anything in `vendor/` was altered. See **Bumping versions** below
  for refreshing the sums after a version change.
- **Image tags must match the operator:** the AWX/EE/postgres/redis tags in
  `manifest.env` must be the ones the chosen operator version deploys, and must
  match the saved tarballs — otherwise pods will try (and fail) to pull. Step 20
  warns if a manifest image isn't present in containerd after import.
- **`ctr: content digest ... not found` on import (step 20):** the saved tarball
  is a multi-arch index missing the other arches' blobs. This happens when you
  fetch with **docker + the containerd image store** and an old `docker save`
  that can't filter by platform. Fixes: (a) use a docker that supports
  `docker save --platform` (Engine v28+) — `fetch-assets.sh` passes it
  automatically; or (b) set `"features": {"containerd-snapshotter": false}` in
  `/etc/docker/daemon.json`, `systemctl restart docker`, then re-fetch. After
  either, delete `vendor/images/*.tar` and re-run `fetch-assets.sh` to regenerate
  the tarballs + `SHA256SUMS`, recopy, and re-run `install.sh`.
- **Architecture:** vendored assets are **amd64** (`k3s` binary and
  `k3s-airgap-images-amd64.tar.zst`, images saved `--arch amd64`). For arm64,
  change the filenames/flags in `manifest.env` + `fetch-assets.sh` and re-fetch.
- **DNS / access:** NodePort works by IP with no DNS. For `ingress`, clients must
  resolve `AWX_HOSTNAME` (real DNS or `/etc/hosts`) and the cert CN/SAN must match.
- **Storage:** PVCs use k3s's built-in `local-path` StorageClass (data under
  `/var/lib/rancher/k3s/storage`). `--purge` deletes all of it.
- **First boot is slow:** the operator initializes postgres and runs migrations;
  pods may restart a few times before settling. No internet is used during this.
- **Bumping versions:** edit `vendor/manifest.env` (and the image tags in it),
  then re-run `fetch-assets.sh` to re-download/re-export the changed assets and
  regenerate `vendor/SHA256SUMS`.
